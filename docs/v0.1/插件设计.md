# v0.1 插件设计

本文定义 v0.1 每个 pulse_* 插件的职责、ECS 组件、系统和依赖关系。

---

## IDL 代码生成

所有 pulse_* 插件的 C API 头文件均通过 IDL（接口定义语言）自动生成。处理流程与语法详见 IDL 文档（待编写）。

| 项目 | 内容 |

| **状态** | 待实现 |

| **依赖** | 无（纯 header） |

纯 header-only 模块，仅做一件事：`#include "handmademath.h"`，提供 `HMM_Vec3`、`HMM_Quat`、`HMM_Mat4` 等类型和运算。其他模块通过 `#include "pulse_math.h"` 统一获取，无需各自寻找 HMM 路径。

## pulse_transform 🆕

| 项目 | 内容 |
|------|------|
| **职责** | ECS 变换组件定义 + 层级关系管理 + 变换传播系统 |
| **状态** | 待实现 |
| **头文件** | `src/pulse_transform/include/pulse_transform.h` |
| **依赖** | pulse_app + pulse_math |

### ECS 组件

```cpp
struct Position     { HMM_Vec3 value; };
struct Rotation     { HMM_Quat value; };
struct LocalTransform  { HMM_Mat4 model; };    // 由 Position/Rotation 计算得出
struct WorldTransform  { HMM_Mat4 value; };    // 由层级传播计算得出
struct ShowMatrix   { HMM_Mat4 model; };       // 插值后的渲染用矩阵
struct Tree {
    ecs_entity_t parent;
    ecs_entity_t firstChild, lastChild;
    ecs_entity_t previousSibling, nextSibling;
};
```

### 系统

| 阶段 | 系统 | 触发条件 |
|------|------|---------|
| PostUpdate | UpdateLocalTransform | 有 Position/Rotation 时自动计算 LocalTransform |
| PostUpdate | PropagateWorldTransform | 遍历 Tree 层级，计算 WorldTransform = parent * local |

### Pipeline 标签

```cpp
struct UpdatePipeline {};
struct PostUpdatePipeline {};
struct RenderPipeline {};
```

## pulse_renderer 🆕

| 项目 | 内容 |
|------|------|
| **职责** | 高层渲染管线框架：封装从 ECS 世界到 GPU 渲染的完整流程 |
| **状态** | 待实现 |
| **头文件** | `src/pulse_renderer/include/pulse_renderer.h` |
| **依赖** | pulse_app + pulse_math + pulse_graphics + pulse_transform + pulse_asset |

### ECS 组件

```cpp
struct Camera {
    ecs_entity_t window_entity;
    float fov, nearPlane, farPlane;
    int width, height;
};
struct Light {
    HMM_Vec4 color;
};
struct Renderable {
    PulseMeshHandle mesh;
    PulseMaterialHandle material;
};
```

### API

```c
// 注册默认渲染管线
EPulseResult pulse_add_renderer_plugin(PulseAppId app, ...);

// 渲染数据包（内部使用）
struct PulseRenderPacket { ... };   // 封装帧数据包
```

### 渲染流程

```
每帧：
  1. simulate  → 更新游戏逻辑（用户 system）
  2. interpolate → 运行 RenderPipeline（计算插值 + ShowMatrix）
  3. extract   → 遍历 Camera，收集可视 Renderable，构建 RenderPacket
  4. submit    → 遍历 RenderPacket，提交到 rendergraph 的 pass
```

具体实现使用 pulse_graphics 的 `AddRenderRecordCallback` 注册回调，在 RenderGraph 构建阶段执行 submit。

## pulse_imgui 🆕

| 项目 | 内容 |
|------|------|
| **职责** | ImGui 作为 pulse 插件集成 |
| **状态** | 待实现 |
| **头文件** | `src/pulse_imgui/include/pulse_imgui.h` |
| **依赖** | pulse_app + pulse_window |

### API

```c
typedef void (*PulseProcImGuiDrawFn)(void* user_data);

EPulseResult pulse_add_imgui_plugin(PulseAppId app, ...);
EPulseResult pulse_imgui_add_draw_callback(PulseAppId app,
    PulseProcImGuiDrawFn callback, void* user_data, int priority);
```

### 实现思路

- 在 pulse_window 的渲染流程末尾插入一个高优先级（如 1000）的 record callback
- 该 callback 创建 ImGui 的渲染 pass，依次调用所有注册的 draw callback

## pulse_dascript_binding 🆕

| 项目 | 内容 |
|------|------|
| **职责** | 各 pulse 模块类型和函数到 DaScript 的 binding 注册 |
| **状态** | 待实现 |
| **头文件** | `src/pulse_dascript_binding/include/pulse_dascript_binding.h` |
| **依赖** | pulse_app + pulse_script_dascript + 各绑定的 pulse 模块 |

### 设计

所有 binding 代码集中放在 `pulse_dascript_binding` 模块下：

```
src/pulse_dascript_binding/
├── include/
│   └── pulse_dascript_binding.h     ← 统一注册入口
└── src/
    ├── pulse_math_das.cpp           ← 注册 HMM_Vec3, HMM_Quat, HMM_Mat4 等数学类型
    ├── pulse_transform_das.cpp      ← 注册 Position, Rotation, LocalTransform, WorldTransform, Tree 等
    ├── pulse_renderer_das.cpp       ← 注册 Camera, Light, Renderable 等
    ├── pulse_asset_das.cpp          ← 注册 AssetHandle 等
    └── pulse_graphics_das.cpp       ← 注册 ShaderHandle, MeshHandle, TextureHandle 等 GPU 句柄
```

`pulse_dascript_binding` 在 build 阶段依次调用各内部模块的注册函数，`pulse_script_dascript` 不关心具体注册了哪些类型。
