# 1. 简介

方案整体类似luban。
schema文件和数据文件分离，tablegen工具通过schema生成数据表的包装（目前是c++和daslang）。底层是pulse_datatable，上层通过自动生成的代码操控pulse_datatable。
schema和数据文件都使用datalist。

# 2. schema文件

一个文件就是一个类型，文件名就是它的类型名。schema的kind由内容自动判定，不需要显式声明：

| kind | 判定条件 | 用途 |
|---|---|---|
| table | 有且仅有一个字段带 `key: true` | 数据表，行有主键 |
| enum | 顶层只有一个 `values` 列表 | 字符串白名单类型，可被多个表的列引用 |
| struct | 其余情况 | 可被其它类型当列类型内嵌的共享结构 |

案例：
```snake.schema
id:
    type: string
    key: true
interval:
    type: float
    default: 1
    min: 0.1
    max: 10
```

顶级键是字段名，二级键是字段属性。主键字段有且只有一个，类型须为 string 或 int。

字段属性：

| 属性 | 含义 |
|---|---|
| `type` | int / float / bool / string / 共享 struct 类型名 / 白名单 enum 类型名 / ref |
| `key` | 主键标记，只有 table 有。类型须为 string 或 int |
| `default` | 缺省值。有此属性的列可缺省（不写 = 填默认）；无此属性的列必填 |
| `min` / `max` | 数值值域，仅 int / float |
| `values` | 字符串白名单（枚举），仅 string |
| `ref` | 外键，指向另一个 table 的类型名 |

`type` 只能写 int / float / bool / string / 共享 struct 类型名 / `ref`。列要指向另一张表的行必须写 `type: ref` + `ref: <表名>`，这样才参与加载期解析与资产依赖排序。

# 3. 数据文件

```
schema: "<类型名>"
rows: [ { ... }, ... ]
```

- `rows` 是列表，每项必须写成 `{ ... }`（不能跨行展开成多键形式）。
- 数据文件不含任何 schema 信息，`schema` 字段只做一致性校验：与注册的类型名不符时报 `schema is not registered`。
- 数据文件名必须与类型名相同（`snake.datatable` → `snake`），loader 用文件名推导类型。
- 主键必须唯一，重复时报错并成对指出两行的文件行号。
- 未知列、缺必填列、类型不符、越界、枚举不在白名单都会在加载期失败，错误信息带文件行号。
- 嵌套 struct 列写 `{ power: 3.5 radius: 2 }`；缺省时整块填默认值，逐层递归。

当前直接读取文本数据文件，未来再做二进制。

# 4. MOD支持

当前文件系统支持后加载的包覆盖前面的包的同名文件。这直接支持MOD覆写某些数据表。属性/记录级的覆盖暂不支持，未来再考虑。一般情况下MOD作者不应该覆写schema，只可以覆写数据文件，即不能操作数据结构。

# 5. 引擎的组成

## 5.1 pulse_datatable

数据表基建，依赖pulse_datalist和pulse_asset。

- 资产类型 `PULSE_TYPE_DATA_TABLE`（0x3000），每种数据文件是独立资产，扩展名 `.datatable`。
- `pulse_data_table_system_register_schema` 是唯一的注册入口，成功返回 `PULSE_RESULT_OK`，失败返回错误码并经 `out_error` 给出引擎持有的错误文本。注册时引擎把描述符（含全部字符串）深拷贝进系统自己的存储，调用方的描述符与数组可以是用完即弃的临时数据。`fill_row` 为空时，引擎从列描述符推导全部字节布局（列偏移、内嵌 struct 的大小与对齐、主键 int 标志、数值默认值的 int/float 互通），并用按列驱动的通用填充器逐行写内存；带 `fill_row` 的静态描述符保持调用方自带的布局（C++ 生成代码的 `offsetof` 路径）。被引用的 struct / 白名单类型内嵌在描述符自己的 `p_structs` / `p_enums` 里，没有跨表共享的类型注册。
- `pulse_data_table_system_load` 发起加载，返回 `PulseAssetRequest`；加载器按 schema 校验并逐行填充平坦内存。通用填充器与生成的 C++ 填充逐列语义一致（缺必填列、类型不符、越界、ref 解析失败等报错文本与行号相同）。
- 行内字符串统一存进表自己的 vault（`std::string_view` 指向 vault，随表存活）。枚举列存校验后的字符串，读出来就是名字。
- `ref` 列在加载期解析成指向目标行内存的指针；引用目标表通过资产依赖自动排到前面，目标表解析失败或行不存在时本表加载失败。
- 每个数据文件是独立资产：同一个 schema 可以从不同路径加载多份，各自由 `PulseAssetRequest` 区分（C++ 侧按 request 取表）。按类型名查表（daslang 侧只能按类型名查）永远取最近加载的那一份。
- 加载完成后 `pulse_data_table_system_get(request)` 拿到 `DataTableId`，再用 `pulse_data_table_rows` / `pulse_data_table_find_row` / `pulse_data_table_find_row_int` 访问。

`pulse_datatable` 不知道任何具体表的结构，全部信息来自运行时注册的 `PulseDataTableSchemaDesc`。

## 5.2 tablegen

独立c++程序，直接依赖pulse_datalist复用解析器，输入schema文件，输出指定语言的数据绑定。

```
xmake build tablegen
tablegen [--out-h <header> --out-cpp <source>] [--out-das <module>.das] <schema文件>...
```

C++输出：

- 每张表一个行结构体 `Pulse<表名>Row`（`alignas` + `static_assert(sizeof)` 锁定布局）和 `Pulse<表名>RowTable`。`<表名>` 是schema文件名的PascalCase形式：`snake_config` → `PulseSnakeConfigRow`。
- struct 输出 `Pulse<结构名>`；enum 不生成 C++ 类型，枚举列在行结构体里就是 `std::string_view`（存白名单名字），被引用的 enum 以 `PulseDataTableEnumDesc` 内嵌进使用它的表描述符。
- 行结构体按依赖顺序排列，指针列另有前置声明，表之间互相引用不依赖文件顺序。
- 每列一个 `PulseDataTableColumnDesc`，`ColumnDescBuilder` 链式构造，偏移由 `offsetof` 得到，min/max/default 直接进描述符。
- `fill_row` 不再是必选项：描述符留空即由引擎按列通用填充，行大小与对齐（偏移、struct 大小对齐）由引擎从列描述符推导，与 `offsetof` 行结构体逐字节一致；生成的 C++ 描述符带自己的 `fill_row`，走 `offsetof` 布局。
- `RegisterSchemas(PulseDataTableSystemId)` 一次性注册全部 schema，重复注册返回错误。
- `Pulse<表名>RowTable`：`Load(app, path = nullptr)`（记住路径，后续调用复用）、`IsReady(app)`、`GetError(app)`、`Rows(app, out_count)`、`GetRow(app, key)`（string 主键为 `const char*`，int 主键为 `int64_t`）、`DefaultPath()`（`<表名>.datatable`）。静态接口没有地方存请求，所以 `Load(path)` 记下的路径就是后续 `IsReady/GetError` 的目标。

daslang输出：

- 一个 `<module>.das`，模块名取自输出文件名，入口模块 require 它即可。
- 每张表生成一个注册函数：用 das 的 `array<PulseDataTableColumnDesc>`（外加 `array<PulseDataTableStructDesc>` / `array<PulseDataTableEnumDesc>`）按 schema 逐列摆描述符，指针字段用 `unsafe { desc.p_columns = reinterpret<void?>(addr(columns[0])) }` 指到数组首元素，然后直接调用 `pulse_data_table_register_schema(app, desc)`（`pulse_data_table_system_register_schema` 的 das 入口）。不需要内嵌 schema 文本，也不需要算偏移——引擎在 `fill_row` 为空时自己推导布局并拷贝进系统存储。首次 `Load` 前惰性注册、进程内一次性，失败时打印错误，游戏代码不需要注册入口。
- 每张表一组函数：`Pulse<表名>Load(app, path = "<表名>.datatable") -> PulseAssetRequest`、`Pulse<表名>IsReady(app, request)`、`Pulse<表名>GetError(app, request)`、`Pulse<表名>RowCount/RowAt/FindRow(FindRowInt)`，以及每个字段的访问器 `Pulse<表名>Get<字段>[<子字段>]`。
- 请求级查询都显式收 `request`，没有任何隐藏状态：脚本把 `Load` 的返回值存进自己的资源/单例，之后一直用它。`GetError` 在未失败时返回空串，可以直接当失败判定。
- daslang 侧不镜像行内存布局，字段访问走 `pulse` 模块的通用读取接口；字符串按值拷成 das string，struct 列按字段路径展开，ref 列返回指向目标行的裸指针，可以继续用目标表的访问器读。

## 5.3 daslang 侧接口

`pulse` 模块新增通用数据表接口（`src/pulse_daslang/src/das_pulse.cpp`）：

| 函数 | 说明 |
|---|---|
| `pulse_data_table_register_schema(app, desc)` | 直接调 `pulse_data_table_system_register_schema`；`desc` 是 das 侧构造的 `PulseDataTableSchemaDesc`（数组指针用 `void?` 手工接线），成功返回空串，失败返回引擎给出的错误信息 |
| `pulse_data_table_load(app, schema, path)` | 加载，返回 `PulseAssetRequest` |
| `pulse_data_table_is_ready(app, request)` | 是否加载完成 |
| `pulse_data_table_get_error(app, request)` | 失败原因，无错误为空串 |
| `pulse_data_table_row_count(app, schema)` | 行数 |
| `pulse_data_table_row_at(app, schema, index)` | 第 index 行指针 |
| `pulse_data_table_find_row(app, schema, key)` | string 主键查行 |
| `pulse_data_table_find_row_int(app, schema, key)` | int 主键查行 |
| `pulse_data_table_read_int/float/bool/string/ref(app, schema, row, c0, c1, c2, c3)` | 按列路径读字段，`-1` 表示路径结束 |

列路径用列下标表示，嵌套 struct 逐层追加，最多四层。生成代码负责把字段名翻成下标，用户只写 `Pulse<表名>Get<字段>`。

描述符类型（`PulseDataTableSchemaDesc` / `PulseDataTableColumnDesc` / `PulseDataTableStructDesc` / `PulseDataTableEnumDesc` 与 `EPulseDataTableColumnType`）以注解形式暴露给 das：`const char*` 字段就是 das `string`，`T*` 指针字段以 `void?` 呈现（das 的 `string` 本身就是 8 字节 `char*`，`array<string>` 的内存就是 `const char**`），`columns_count` 等 `size_t` 计数是 das `uint64`。das 用 `push <| PulseDataTableColumnDesc(name = "...", column_type = ...)` 摆数组，再用 `unsafe { desc.p_columns = reinterpret<void?>(addr(columns[0])) }` 接线——数组在整个调用期内保持存活即可，注册调用完成时数据已被引擎拷走。`type` 是 das 关键字，所以列类型字段在 das 侧叫 `column_type`；`struct_size` / `version` / `fill_row` 由绑定代填，das 不用管。

# 6. 使用流程

1. 写 `.schema`，用 tablegen 生成绑定（C++ 与 daslang 至少生成一个，纯 daslang 包只需 daslang）。
2. C++ 侧启动时 `pulse_tables::RegisterSchemas(pulse_get_data_table_system(app))` 注册全部 schema；daslang 侧不需要注册入口，生成的 `.das` 在首次 `Load` 前用描述符数组自动注册。
3. `Pulse<表名>RowTable::Load(app)` 或 das 的 `Pulse<表名>Load(app)` 发起加载，等 `IsReady`。
4. 加载完成后 `GetRow` / `FindRow` 取行，直接读字段；das 侧用 `Get<字段>` 访问器。

## 6.1 纯daslang游戏怎么注册schema

daslang 包不需要携带任何 native 库：生成的 `.das` 用 das 数组搭 `PulseDataTableSchemaDesc`，直接调 `pulse_data_table_register_schema`，布局与行填充都在引擎里完成。`examples/snake_daslang/` 就是纯 daslang 包：`package.json` 只声明 `type: "daslang"` + `script_file`，`pulse_tables.das` 里 `snake_config` 的两列以 `array<PulseDataTableColumnDesc>` 形式声明，在 `PulseSnakeConfigLoad` 里惰性注册。

（包加载器仍支持 `library` + `entry` 与脚本并存的混合包，但数据表不再需要它。）

# 7. 示例

- `tests/datatable/`：`test_basic.cpp` 覆盖主键、嵌套 struct、ref、枚举、默认值与各类加载失败的错误文本，`test_mod.cpp` 覆盖 MOD 同名文件覆写，`test_daslang.cpp` + `das/pulse_tables.das` + `das/probe.das`：测试表全部由 das 侧用描述符数组注册（走引擎推导布局 + 通用填充），probe 校验数值并覆盖 daslang 侧的全部访问器；C++ 侧再对照 `offsetof` 断言引擎推导的列布局与生成行结构体逐字节一致。
- `examples/snake/`：C++ 版蛇，开局加载 `assets/snake_config.datatable`，用表里的 `move_interval` 建 `SnakeMove`。
- `examples/snake_daslang/`：纯 daslang 版蛇，同样从 `assets/snake_config.datatable` 读 `move_interval`，`pulse_tables.das` 用 das 数组搭描述符并直接调注册接口。
