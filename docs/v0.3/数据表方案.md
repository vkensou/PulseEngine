# 1. 简介

方案整体类似luban。
schema文件和数据文件分离，tablegen工具通过schema生成数据表的包装（目前需要c++和daslang）。底层是pulse_table，上层通过自动生成的代码操控pulse_table。
schema和数据文件都使用datalist。

# 2. schema文件

案例：
```snake.schema
$key: id
id:
    type: string
interval:
    type: float
    default: 1
    min: 0.1
    max: 10
```

一个文件就是一个类型，文件名就是它的类型名。`$key` 表示主键字段名，有且只有一个，类型须为 string 或 int。顶级键是字段名，二级键是字段属性

字段属性：

| 属性 | 含义 |
|---|---|
| `type` | int / float / bool / string / 枚举 / 共享 struct 类型名 / ref |
| `default` | 缺省值。有此属性的列可缺省（不写 = 填默认）；无此属性的列必填 |
| `min` / `max` | 数值值域 |
| `values` | 字符串白名单（枚举） |
| `ref` | 外键目标表名 |

# 3. 数据文件

```
schema: "<类型名>"
rows: [ { ... }, ... ]
```

- `rows` 是列表，每项是一个行对象，必须含 `$key` 声明的列。
- 主键必须唯一，重复报错须成对指出两行的文件行号。
- 数据文件不含任何 schema 信息。

当前直接读取文本数据文件，未来再做二进制。

# 4. MOD支持

当前文件系统支持后加载的包覆盖前面的包的同名文件。这直接支持MOD覆写某些数据表。属性/记录级的覆盖暂不支持，未来再考虑。

# 5. 引擎要做什么

开发pulse_datatable作为数据表基建，依赖pulse_datalist和pulse_asset。实现程序tablegen，输入scheme，输出指定语言的数据绑定程序。用户可以直接使用pulse_datatable库，也可以使用生成代码简化操作。
