### 3.贴图使用ktx处理

已实现：KTX2 全格式加载（未压缩 RGBA8、原生 BC/ETC2/ASTC、UASTC、ETC1S、zstd 超压缩），Basis 运行时转码按设备能力回退（BC7→BC1/BC3→ASTC4x4→ETC2→RGBA32 无条件兜底），原生块格式不支持时显式失败并提示从母格式重转。几何覆盖 2D / cubemap / 2D array / cube array / 3D / 1D（1D 按 height=1 的 2D 上传）；运行时 mipmap 按**最终上传格式**是否未压缩决定，逐 slice（面/层/面×层）各推一条链，3D 一律不生成，块压缩只 warning 按层上传。原生 `R8G8B8` 在缺 SAMPLE 位的设备上 CPU 展开成同 transfer 的 RGBA8 回退。见 `docs/v0.3/ktx2贴图加载设计.md`（§11、§12 为两轮复核/落地记录，§13 是 loader 设置段的不变式护栏）与 `tools/ktx/README.md` §9。探针已把维度与上传格式做成 render graph 读回硬断言（1D→`256x1x1`、3D→`32x16x8`、数组/cube/cube array→`64x64x1`，RGB8 回退断言格式集合命中 RGBA8 侧），"3D 不生成 mip"的守卫分支也由 `tex_3d_32x16x8_rt.ktx2` 实跑坐实（护栏 printf 恰好一次、该资产无生链行）。遗留：转码移工作线程、裁剪 BASISD_SUPPORT_ATC/FXT1/PVRTC1/PVRTC2 减包体（本期按约定暂不裁）、`mip_levels`/`array_size` 缺 getter 只能继续靠 loader 日志取证、逐资产渲染像素与 `baseline.png` 的比对。

### 5.数据表

已实现。`pulse_datatable` 依赖 `pulse_datalist` + `pulse_asset`，提供 `PULSE_TYPE_DATA_TABLE`（0x3000）资产类型与运行时注册的 schema 表；`tools/tablegen` 读 `.schema`，输出 C++ 绑定（行结构体 + 列描述符 + `fill_row` + `RegisterSchemas` + 每表 `Load/IsReady/GetError/Rows/GetRow`）与 daslang 绑定（每表 `Load/IsReady/GetError/RowCount/RowAt/FindRow` + 每字段访问器）。schema 与数据文件都用 datalist，kind 由内容自动判定（有 `key: true` 是 table、有 `values` 是 enum、其余是共享 struct）。加载器按 schema 校验每行（缺列/未知列/类型/值域/枚举/主键唯一/引用存在），字符串进表内 vault，`ref` 列在加载期解析成行指针并由资产依赖保证目标表先加载；错误信息带文件行号，重复主键成对给出两行行号。MOD 覆写沿用文件系统同名覆盖（只覆写数据文件）。daslang 侧不镜像行内存，`pulse` 模块暴露通用数据表读写接口，脚本用生成的访问器读字段。测试：`tests/datatable/`（三个测试：C++ 基础覆盖 string/int 主键、嵌套 struct 三层、ref、枚举、默认值与各类加载失败的错误文本，MOD 覆写，daslang 侧全部访问器）。两个蛇示例都用上了数据表：`examples/snake` 与 `examples/snake_daslang` 都从 `assets/snake_config.datatable` 读 `move_interval` 建 `SnakeMove`；daslang 包用「daslang 脚本 + native 库」的混合包形式注册 schema（包加载器已支持同一包同时声明 `script_file` 与 `library`/`entry`）。详细方案与用法见[数据表方案](数据表方案) 与 `tools/tablegen/README.md`。
