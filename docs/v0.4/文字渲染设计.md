# 文字渲染设计（pulse_font + pulse_text）

v0.4 目标是复刻几个桌游，文字需求聚焦在**卡牌上显示文字**：卡名、带颜色关键词的描述、内联图标。本文给出分层方案、包划分、接口形态与落地顺序。

## 1. 结论先说

1. 文字渲染拆成**两个新包**，不是一个：`pulse_font`（字形层：字体解析、度量、SDF 图集、fallback、最小绘制出口）与 `pulse_text`（排版层：断行、对齐、行高、富文本标签、measure）。两层之间只有单向依赖：pulse_text 调 pulse_font 的度量与图集查询接口，不碰纹理和 GPU。
2. **不建 pulse_ui**。卡牌文字最终要变成带纹理的 quad 提交出去，这条最小 2D 绘制路径（正交 pass + instanced quad + SDF shader）作为 pulse_font 的渲染出口先做出来，照 `pulse_imgui` 的 rendergraph 接法。将来若做 pulse_ui，这个提交接口整体上移，字体层与排版层不动。
3. 字形解析用 **stb_truetype**，不用 FreeType：单头文件、无许可证负担、vendor 进 `src/pulse_font/src/` 即可，符合最小核心；FreeType 的收益（hinting、变量字体）当前用不上，且 SDF 管线本身对 hinting 不敏感。
4. 图集用**单通道 8bit SDF**（精确欧氏距离变换生成），所有字号从基准尺寸缩放采样，`fwidth` 做屏幕空间抗锯齿。卡牌有悬停放大、拖拽缩放、整桌缩放，SDF 一份图集覆盖所有缩放且保持清晰，这是位图方案做不到的。
5. **fallback 链是刚需**：卡牌文字 = 中文 + 数字 + 符号 + 可能的英文混排，主字体缺字必须能落到兜底字体，否则出豆腐块。第一版做有序字体链（主字体 → 兜底 CJK 字体）即可。
6. 当前范围**明确砍掉**：逐字命中测试、光标查询、IME、文本输入、Yoga measure 回调、下划线、复杂 shaping（HarfBuzz）。这些是完整 UI 文字系统的需求，卡牌显示用不上；接口分层保证将来补的时候不动已有两层。

## 2. 目标与非目标

**目标**

- 从内存字节流注册 TTF/OTF 字体（含 TTC 多 face），家族名 → 字体 id 注册表。
- glyph 度量：advance / bearing / ascent / descent / lineGap / kerning。
- SDF 字形图集：固定槽位 + LRU + 脏区回传 GPU；按字号分档光栅化。
- 有序 fallback 链，按 codepoint 解析实际字体。
- 最小绘制出口：glyph 实例流 → 一次 instanced draw，接入 rendergraph。
- 排版窄版：给定盒子宽度断行、水平/垂直对齐、行高、基线；输出 glyph 实例流。
- 富文本：颜色标签 + 内联图标（第一版接口就留位置，见 §5.4）。
- 加载期字符集预热：用卡牌/本地化文本预扫字符，一次性烘图集，避免出牌瞬间光栅化卡顿。卡牌游戏字符集有限，收益高、成本低。

**非目标（明确边界，后续单独排期）**

- 逐字命中测试、光标定位、IME、文本编辑。
- 系统字体读取（Windows GDI / macOS CoreText / Linux fontconfig）：桌游卡牌自带风格字体，bundled TTF 够用。
- 复杂文种 shaping（阿拉伯连写、印度系重排）：不引 HarfBuzz。但 pulse_font 内部把"文本 → glyph run"做成可替换的一步（先用 codepoint + kerning 的简单实现），将来要接 shaping 只换这一步。
- 竖排、双向文本（BiDi）。
- 文本撑开容器（measure 回调进布局系统）：卡牌文字盒子是卡面模板定死的固定尺寸；超长自动缩字号是排版层一个小分支，可以后补。
- MSDF（多通道距离场）：单通道 SDF 对卡牌字号足够；若将来大字号描边/圆角有需求再评估，图集格式变化被隔离在 pulse_font 内部。

## 3. 分层与依赖

```
pulse_text  ──度量/图集查询──▶  pulse_font  ──纹理/pass──▶  pulse_graphics (rendergraph, cgpu)
                                    │
                                    └── stb_truetype (vendor, 包内私有)
```

- `pulse_font` 依赖 `pulse_graphics`（纹理创建、pass 接入），对外暴露 capi。
- `pulse_text` 只依赖 `pulse_font`，**纯 CPU**，无 GPU 类型出现在接口里。排版结果是一批 glyph 实例（矩形 + uv + 颜色），由调用方交给 pulse_font 的提交接口绘制。
- 两包的公共头文件均走 IDL 生成（`src/pulse_font/include/pulse_font.h`、`src/pulse_text/include/pulse_text.h`），`package_register.cpp` 用生成工具产出，禁止手写。

这样切的收益：pulse_text 的断行/对齐/富文本逻辑可以在 `tests/pulse_text` 里纯 CPU 跑 `xmake test`，不需要窗口；pulse_font 的度量与图集 packing 同样纯 CPU 可测，只有 SDF 上传和 draw 需要窗口验证。

## 4. pulse_font 设计

### 4.1 字体注册表

- `register(memory)` → 字体 id；解析 name table 取家族名，TTC 按 index 展开多个 face。
- 家族名 → id 查询；枚举已注册家族名。
- 字体上限先定 64（含 fallback 兜底字体），超出报错而不是静默截断。
- fallback 链是一等公民：`font_chain_create({id...})` 返回链句柄，按 codepoint 依次试链上字体，全缺时落到内置的"缺字方块"glyph（可视化报错优于静默空白）。排版层只认链句柄，不直接拿字体 id。

### 4.2 度量

以基准光栅尺寸归一化存储（int16 或 float 均可，接口对外统一 float、按目标字号换算）：

- `advance(chain, codepoint, size)`、`bearing`、`kerning(chain, cp_a, cp_b, size)`。
- `font_height(chain, size)` → ascent / descent / lineGap，排版层行高的唯一来源。
- 空格等无轮廓 codepoint 的 advance 需要兜底（借用同字体某常规字符的 advance），否则断行算出的宽度会错。

### 4.3 SDF 图集

- 单张 2048×2048 R8 起步，64×64 槽位 = 1024 槽；基准光栅尺寸 48px（64 − 8×2 padding）。
- **图集 key = (font_id, codepoint, size_tier)**。这是与"单基准缩放到所有字号"的关键差异：48px 基准在 96px 大字号下 SDF 精度不够。size_tier 按请求字号向上取档（默认档位 {48, 96}，卡牌正文全落 48 档，仅大标题进 96 档、槽位相应放大）。档位表在图集创建时定死，运行期不可变——将来改 key 是伤筋动骨的事，现在就要做对。
- 查找：开放寻址哈希；淘汰：LRU 整槽回收。
- **多图集扩展**：一屏中文轻松逼近 1024 槽，纯 LRU 会抖动（反复淘汰又重烘）。策略是先扩图集（第二张、第三张 2048²），全部满了才进 LRU 淘汰。图集张数上限（先定 4）到了以后淘汰最旧图集整张回收。
- 生成算法：精确欧氏距离变换（Felzenszwalb 1D EDT 两遍扫描），8bit 输出，radius/cutoff 与基准字号可配。
- 脏区追踪：光栅化只标脏槽位，帧边界把脏区上传，不做整图重传。**当前实现退化为整页上传**：cgpu 的 buffer→texture transfer 没有 region 参数（`CGPUBufferToTextureTransfer` 只有 `src_offset`），而 cgpu 是上游 submodule，改它会引入跨仓库补丁。因此每页维护 `dirty` 标志，帧边界把整页打包成一次 upload pass；预热覆盖了出牌路径，实际只有新字符首次出现的那一帧会付这份带宽。将来 cgpu 支持 region copy 时，这里的改动只在 pulse_font 内部。
- 线程：光栅化可以放工作线程，图集写入与哈希更新加锁；上传必须在渲染线程帧边界执行，dirty 标志驱动。**当前实现是单线程**：光栅化在调用线程完成，`prewarm` 已把批量预烘放在加载期，卡牌场景没有可感知的卡顿，避免为尚不存在的并发需求引入锁。
- 预热接口：`prewarm(chain, utf8_text, size)` 批量光栅化，供加载期扫全部卡牌文本调用。

### 4.4 最小绘制出口

- SDF shader：顶点着色器用 vertex/instance index 现场展开 quad 四角，**每个 glyph 只占一条 instance 数据**，不进顶点缓冲。instance 布局走可读性优先：`float4 rect`（屏幕空间 x, y, w, h）、`float4 uv_rect`、`uint32 color`（RGBA 打包）。不做定点数打包压缩，牺牲一点带宽换可维护性。
- fragment 用 `fwidth` 做屏幕空间抗锯齿，缩放时线宽自适应。
- 正交投影直接算 NDC，无相机。
- 纹理与 sampler 走 `pulse_graphics` 现有创建路径（同 `pulse_imgui` 的 font texture：create → poll alive/ready → handle），rendergraph 侧 import texture + pass sample，接法照抄 `src/pulse_imgui/src/imgui_render.cpp`。
- 提交接口：`submit(instances, count, transform)`，一个 transform 一批 instance 一次 draw。卡牌场景的用法是"卡牌画完 → 该卡文字的实例流一次 submit"，顺序即层级；文字图集纹理与卡面纹理不同，天然分开 draw，不追求合批到同一个 call。
- 裁剪：第一版支持 scissor rect（卡牌文字区裁剪够用），裁剪栈留给将来的 UI 层。

### 4.5 依赖与加载顺序

分层要求"没有 GPU 也能用度量与图集"，这条直接决定了依赖怎么声明：

- `PulsePluginDesc.dependencies`（插件 build 顺序）只有 `pulse_vfs`。pulse_font 的 CPU 层（注册表、度量、图集、SDF）不碰 ECS 与 GPU，`tests/pulse_font` 与将来的 `tests/pulse_text` 因此可以纯 CPU 跑，不需要窗口。
- `package.json.dependencies` 额外声明 `pulse_graphics`，这是**二进制加载顺序**而不是插件依赖：发布布局里每个包一个目录，各自只放自己的 dll，`pulse_font.dll` 对 `pulse_graphics.dll` 的导入必须靠"同名模块已在进程里"来解析（与 `pulse_imgui` 同理）。loader 按 `package.json` 拓扑排序，先加载 graphics 家族。
- 图形资源（shader / material / instanced mesh / 图集纹理）在 `post_build` 里检测到 `pulse_get_renderer` 存在时才创建，`submit` 在没有 graphics 插件时返回 `PULSE_RESULT_ERROR_INVALID_STATE`，不做 fallback。

## 5. pulse_text 设计

### 5.1 核心对象：text block

```
block = create(font_chain, size, color, align_h, align_v, line_height)
layout = block_layout(block, utf8_text, box_w, box_h)   // 排版，产出 glyph 实例流 + 实际占用尺寸
measure = block_measure(block, utf8_text, box_w)        // 只算不排，产出尺寸
```

- `block_layout` 输出 glyph 实例数组（矩形相对盒子原点 + uv + 颜色），调用方叠加卡牌 transform 后交给 pulse_font 的 submit。
- `block_measure` 与 layout 共用同一套断行代码，保证 measure 结果与实际排版严格一致（不允许两套实现）。

### 5.2 断行规则

- 贪心断行：CJK 字符任意位置可断；拉丁按词断（词超宽时退化为字符断）；断行点回退时吃掉行尾空格宽度。
- 对齐：水平 L/C/R（按行实际宽度偏移），垂直 T/V/B（按总行高在盒子内偏移）。
- 行高 = ascent + descent + lineGap，可被 block 的 line_height 系数覆写；基线位置逐行累计，作为 glyph 摆放的唯一依据。
- kerning 在摆 glyph 时逐对应用（度量来自 pulse_font）。
- 超出 box_h 的行截断丢弃，layout 结果带 out_of_box 标志，调用方可据此触发缩字号重试。

### 5.3 measure

- 单行：`measure(text, size)` → width/height。
- 带换行：`measure(text, size, wrap_width)` → 排版后总尺寸。
- 这是将来接布局系统 measure 回调的同一接口，现在只被"缩字号重试"和游戏侧逻辑消费。

### 5.4 富文本标签

第一版接口就带标签解析（排版与标签耦合，后补要重写断行循环）：

- 颜色标签：`[rrggbb]` 切换后续文字颜色，`[/]` 或显式重置标签恢复 block 默认色。
- 内联图标：图标注册表 `icon_register(name, bitmap)` → 图标走与字形相同的 SDF 通道进图集（伪字体 id），排版时 `[icon:name]` 当作一个 advance 已知的"字符"参与断行。卡牌上的资源图标嵌在描述文字里靠这个实现。
- 字号标签暂不做（卡牌上字号由卡面模板决定），语法空间留着。
- 标签解析在排版入口一次完成，产出"带样式 run 的纯文本"中间表示，断行循环只面对 run，不感知标签语法。

### 5.5 缓存

排版结果由调用方（游戏侧）缓存：卡牌文字只在数据变化时重排。pulse_text 自身无状态、不持有缓存——这与引擎"数据驱动 + 显式失效"的方向一致，避免包内长出隐式生命周期。

## 6. 落地顺序与验收

每步独立产出可验证成果，避免一次性做完整条链：

| 步骤 | 内容 | 验收 |
| --- | --- | --- |
| 1. pulse_font 核心 | stb_truetype vendor、注册表、度量、EDT SDF、图集 + 哈希 + LRU、脏区上传 | `tests/pulse_font` 纯 CPU：度量数值、EDT 对合成位图的精确性、图集 packing/淘汰；窗口验证：一段中英文混排画到屏幕，12–96 字号及缩放下清晰 |
| 2. 最小绘制出口 | SDF shader、instanced 提交、rendergraph pass、scissor | 1000 个 glyph 一次 draw call；带窗口测试用 test-tool-for-program-with-window 截图比对 |
| 3. pulse_text 窄版 | 断行/对齐/行高/kerning、measure、fallback 链接入 | `tests/pulse_text` 纯 CPU：CJK/拉丁混排断行、对齐、超长截断、measure 与 layout 一致性 |
| 4. 富文本 + 预热 | 颜色标签、内联图标、prewarm | 用一张真实卡牌数据（卡名 + 带颜色关键词的描述 + 内联图标）复刻卡面文字区，作为端到端验收靶 |

规模预估：步骤 1、3 各一周内，步骤 2、4 各几天；总量约三周。

## 7. 工程约定

- 两包均按现有插件形态落地：`src/pulse_font/`、`src/pulse_text/`，xmake.lua 加 target，`package.json` manifest，公共头文件与 package_register 走 IDL/生成工具，禁止手改。
- stb_truetype vendor 到 `src/pulse_font/src/`，不对外暴露任何 stb 类型。
- 测试：`tests/pulse_font/`、`tests/pulse_text/`，纯 CPU 部分进 `xmake test`；带窗口验证单独 target，按 skill 流程跑。
- daslang 绑定：卡牌数据大概率从数据表来、游戏逻辑可能走 daslang，两包 capi 稳定后补 daslang 侧绑定（排版接口天然适合脚本调用），本期不做。

## 8. 开放问题

1. **卡牌本体当前有没有渲染路径**（卡面图、框的 2D 绘制）？有则步骤 2 的文字 pass 单独加一个 draw 搭车；没有则最小 2D quad 绘制要先修路，步骤 2 的范围会扩大。动手前需要确认。
2. 富文本标签的最终语法（`[icon:name]` 的命名规则、颜色标签是否需要 alpha）在步骤 4 前定稿。
3. 字体资产来源与授权：桌游复刻需要确定 bundled 字体（正文字体 + 兜底 CJK 字体）的具体选型和许可证。
